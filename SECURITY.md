# Security Policy

## Scope

This policy covers the repository `Def-Chigga/def-chigga.github.io` and the
site published from it at <https://def-chigga.github.io>.

It covers two kinds of reports:

1. **Security issues** in the site source or build: exposed secrets, unsafe
   workflow configuration, dependency vulnerabilities, XSS in site components.
2. **Content issues**: material that infringes copyright or trademark, or that
   otherwise conflicts with the GitHub Terms of Service or Acceptable Use
   Policies.

## Reporting a security issue

Please **do not** open a public issue for a security problem.

- Email: `defchigga@qq.com` with the subject prefix `[SECURITY]`.
- Include: affected file or URL, a description of the issue, steps to
  reproduce, and the impact you believe it has.
- If the issue is an exposed credential, say so in the subject line
  (`[SECURITY] exposed credential`) so it can be handled first.

The author aims to acknowledge a report within 7 days and to publish a fix or
a mitigation plan within 30 days for confirmed issues. These are targets, not
guarantees; this is a personal project with no paid support.

## Reporting a content or copyright concern

For an informal report:

- Open an issue on this repository, or
- Email `defchigga@qq.com`.

Include:

- Identification of the work you claim is infringed.
- The URL or repository path where the material appears.
- Your contact details and a good-faith statement that the use is not
  authorized.

The author will review the report and remove, attribute, or otherwise respond
in line with the rights of the parties involved.

## Formal DMCA notices

A formal takedown notice must go to GitHub, not to the repository author, so
that it is processed under GitHub's DMCA policy. See:

- <https://github.com/contact/dmca>
- <copyright@github.com>
- GitHub Terms of Service, section F
  <https://docs.github.com/en/site-policy/github-terms/github-terms-of-service#f-copyright-infringement-and-dmca-policy>

## Out of scope

- Reports about other GitHub accounts or repositories.
- Reports about services this site merely links to.
- Automated vulnerability scanner output without a demonstration of impact.

## Safe harbor

The author will not pursue legal action against a researcher who reports a
vulnerability in good faith, avoids privacy violations, avoids data
destruction, and gives reasonable time to fix the issue before public
disclosure.
